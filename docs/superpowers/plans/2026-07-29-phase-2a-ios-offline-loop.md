# Phase 2a — iOS Offline Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A SwiftUI iOS app implementing spec §16 Phase 2a — local-first store, sync engine against the deployed 1c protocol, Supabase auth with Keychain, pending-queue badge and export, dashboard, ingredient list/detail, purchase entry with local fuzzy pick, settings, and member management — with the Swift kernel passing `shared/golden-vectors.json` byte-for-byte as the contract's third implementation.

**Architecture:** All logic lives in `ios/CostSauceKit`, a local SPM package with platforms iOS 26 + macOS 26 so its entire test suite runs headless via `swift test` on this Mac (no simulator). The app target `ios/CostSauce` is thin SwiftUI generated by XcodeGen from `ios/project.yml`; everything computable is in the Kit and unit-tested. The local GRDB store is the source of truth (spec D2): the dashboard, costing, and drift are computed locally by the Swift kernel over synced rows — the app never calls `/locations/{id}/dashboard`. Server round trips are: sync push/pull, auth, bootstrap (`/config`, `/me`, locations), and the online-only management routes (location settings, members, export).

**Tech Stack:** Swift 6 (Xcode 26.6, min iOS 26.0), SwiftUI, Swift Testing (`import Testing`) for Kit tests, XCUITest for the smoke, GRDB ≥ 7.0 (the only third-party dependency, Kit-only), XcodeGen (installed via brew, project file not committed).

## Global Constraints

- **Backend is read-only this phase except Task 1's additive roster route.** No existing route/response shape changes. `web/`, `shared/`, `product/`, `supabase/` untouched (no new migrations — 1c's schema is complete for 2a).
- **Decisions (Travis, 2026-07-29):** conflict policy is **silent LWW** — no "changed on another device" UI anywhere; min deployment target **iOS 26.0**.
- **Money/decimals are STRINGS** end-to-end: wire, GRDB columns, view rendering (verbatim + "—" for nil, web parity). Arithmetic only through the kernel's `Int128` rationals. `Double`/`Float` never touch money, qty, or pct (B3). No `Decimal` either — the kernel's rationals are the one math path.
- **Dates:** `purchased_on` is `"YYYY-MM-DD"`; all date arithmetic via integer civil-date math (`Kernel.dayNumber`/`dayToIso`), never `Date`/`Calendar` arithmetic (B5). `client_mutated_at`/`recorded_at`/`deleted_at` sent as `Kernel.canonicalTimestamp` (`yyyy-MM-dd'T'HH:mm:ss.SSSSSS'Z'`, UTC) — the server 422s offsetless timestamps (`api/models.py:139-145`).
- **Ids are client-minted UUIDv7**, lowercase strings (spec §4.2/§4.3).
- **The three sync-contract warnings in `api/routes/sync.py:5-29` are binding:** (a) never feed `POST /sync`'s `cursor` into `GET /sync?since=` — only GET's own cursor advances the pull cursor; (b) recipe tombstones don't fan out server-side — moot in 2a because recipes/recipe_items are **pull-only** (editing is 2b); (c) the device kernel owns `qty_base_units` — the server replicates it unvalidated, so the golden vectors are the only backstop.
- **Suppress `suggested_price` in every view while sync state ≠ caught-up** (spec §5.5). Show "syncing…" placeholder instead.
- **Never let a server-side problem cost the owner local data** (§13): 401 → hold queue, re-auth prompt; 410 → freeze writes, offer export, wipe only on explicit confirm; identity switch → refuse flush, offer export, explicit "switch and erase".
- **Sync apply limits:** `MAX_BATCH_OPS = 200`, `SYNC_PAGE_CAP = 500` (server; `api/services/sync.py:21-22`). Op `fields` keys must be subsets of the server's `INSERT_FIELDS`/`UPDATE_FIELDS` allowlists (`sync.py:25-38`) or the op parks as `needs_attention`.
- **Test gates after every task:** `cd ios/CostSauceKit && swift test` green; `uv run --extra dev pytest -q` green for Task 1 (and unchanged thereafter); app target builds from Task 2 on: `cd ios && xcodegen generate && xcodebuild -project CostSauce.xcodeproj -scheme CostSauce -destination 'generic/platform=iOS Simulator' build -quiet`.
- **Commits:** one per task — `feat(2a): …` / `test(2a): …` / `docs(2a): …`.
- **Out of scope (do not build):** recipe create/edit/delete UI (2b); invoice capture/OCR (Phase 3); SIWA and the §6.1 connect flow — its backend was descoped in 1a (`api/routes/identity.py:37-73` lists the prerequisites; must land before Phase 5); CSV import (web-only, spec §16); push notifications (Phase 4); deletion-*initiation* UI (Phase 5 prep — but 410 *handling* and org export ship now); multi-location UI (§17 — the location picker handles >1 by asking once).

Behavior (frozen — each numbered rule is a test):
1. `syncNow` = **pull loop → push → pull loop**. Pull loop: `GET /sync?since=<meta.cursor>` repeatedly; each page → `store.applyPullPage(changes, cursor: page.cursor)` (atomic; cursor advances per page so a killed app resumes mid-stream); state `catchingUp` while `hasMore`, `caughtUp` when a loop ends with `hasMore == false` and no push work remains.
2. Push: queued ops in `(created_at, op_id)` order, chunks of ≤ 200, fresh `batchId` (UUIDv7) per chunk, `opId` stable across retries (the server's idempotency ledger dedupes, §5.3). Per result, positionally zipped with the sent ops: `applied`/`replayed` → if `rowId != nil && rowId != op.row_id` → `store.adoptCanonicalRow` then `deleteOp`, else `deleteOp`; `stale` → `deleteOp` (server was newer — silent LWW; server truth lands on the trailing pull); `needs_attention` → `markNeedsAttention(reason)` — terminal, never auto-retried (§5.5); Task 14's UI resolves it.
3. **`POST /sync`'s response `cursor` is never written to meta** (sync.py warning (a)) — only the trailing pull loop advances the cursor.
4. `ApiError.status == 401` → state `blocked(.authRequired)`; queue untouched (§13). (The app layer separately flips SessionController via `onUnauthorized`.)
5. `ApiError.status == 410` → state `blocked(.orgDeleted)` (§6.2); no ops deleted — the export path needs them; Task 14's flow discards the queue only via user-confirmed wipe.
6. `URLError`/transport failure → state `blocked(.offline(localizedDescription))`; the next `syncNow` retries everything. No timers in the Kit — the app layer triggers sync on launch, on foregrounding, and (debounced) after each local edit.
7. The engine never mutates ops except via rules 2's outcomes; no reordering, no merging.

`FakeSyncServer.swift`: an in-process contract double mounted via the StubTransport URLProtocol: canonical rows per table, a global monotonically-allocated `server_seq`, paged pulls with configurable page size, push apply with the server's exact result vocabulary — `replayed: true` on op_id re-use, `stale/older` when its stored `client_mutated_at` is newer, `needs_attention` with reason strings, whole-batch 410 and 401 toggles. ## Locked decisions (do not relitigate mid-task)

- Silent LWW; iOS 26.0 minimum (Travis, 2026-07-29). The Kit targets macOS 26 too purely so `swift test` runs headless.
- GRDB is the only third-party dependency; auth is hand-rolled GoTrue REST (web-client parity); no Supabase SDK, no other packages.
- The local store is the source of truth: dashboard/drift/costing are computed on-device by the Swift kernel; iOS never calls `/locations/{id}/dashboard`.
- Store values are verbatim wire strings, except timestamps canonicalized once at apply/mint time; `unit_price` is always computed locally, never read from the stored column.
- Recipes and recipe_items are pull-only in 2a (editing is 2b); ingredient merge UI is web-only in 2a.
- iOS auth uses the emailed OTP code, not magic-link deep links — no universal-link setup in 2a.
- XcodeGen generates the project; `*.xcodeproj` is never committed.
- One backend addition only (the roster route); everything else server-side is frozen.
